# Код Геммінга

Дві незалежні консольні програми C# виконують завдання:

- `Encode/HammingEncode.cs` кодує файл або рядок кодом Геммінга.
- `Decode/HammingDecode.cs` відновлює дані та виправляє одну бітову помилку в кожному кодовому блоці.

Використано розширений код Геммінга `(8,4)`: із чотирьох інформаційних бітів утворюється блок із восьми бітів. Він виправляє одну помилку та виявляє дві помилки в одному блоці. Дані збільшуються вдвічі: код додає перевірочні біти для захисту від помилок.

## Збирання

Потрібен .NET SDK 8. Усі команди нижче виконуються з кореня репозиторію `cki`.

```powershell
dotnet build HammingCoding/Encode/HammingEncode.csproj -c Release
dotnet build HammingCoding/Decode/HammingDecode.csproj -c Release
```

## Файли

```powershell
dotnet run --project HammingCoding/Encode/HammingEncode.csproj -c Release --no-build -- input.txt encoded.ham
dotnet run --project HammingCoding/Decode/HammingDecode.csproj -c Release --no-build -- encoded.ham restored.txt
```

Можна передати декодеру тільки вхідний файл:

```powershell
dotnet run --project HammingCoding/Decode/HammingDecode.csproj -c Release --no-build -- encoded.ham
```

Результат збережеться як `encoded.ham.restored`. Програми працюють із байтами, тому підходять для тексту, зображень та інших файлів. Наявний вихідний файл не перезаписується. Для повторного запуску потрібно вказати нове ім'я вихідного файла.

## Рядки та внесення помилки

Рядок перетворюється на UTF-8. Закодовані байти виводяться як Base64, щоб їх можна було скопіювати як текст.

```powershell
$encoded = dotnet run --project HammingCoding/Encode/HammingEncode.csproj -c Release --no-build -- --text 'Привіт, світе!'
dotnet run --project HammingCoding/Decode/HammingDecode.csproj -c Release --no-build -- --text $encoded
```

Щоб перевірити виправлення, змінюємо один біт закодованих байтів і передаємо пошкоджений результат декодеру:

```powershell
$bytes = [Convert]::FromBase64String($encoded)
$bytes[0] = [byte]($bytes[0] -bxor 0x80)
$damaged = [Convert]::ToBase64String($bytes)
dotnet run --project HammingCoding/Decode/HammingDecode.csproj -c Release --no-build -- --text $damaged
```

Результатом знову буде `Привіт, світе!`. Помилка вноситься в кодовий блок, а Base64 лише представляє його у вигляді тексту.

Для файла можна зробити те саме:

```powershell
$bytes = [IO.File]::ReadAllBytes('encoded.ham')
$bytes[0] = [byte]($bytes[0] -bxor 0x80)
[IO.File]::WriteAllBytes('damaged.ham', $bytes)
dotnet run --project HammingCoding/Decode/HammingDecode.csproj -c Release --no-build -- damaged.ham corrected.txt
```

Ці приклади передбачають непорожній вхід. Порожні файли й рядки також підтримуються, але в них немає бітів для зміни.

## Як працює кодування

Кожен початковий байт ділиться на дві частини по чотири біти: спочатку старша, потім молодша. Кожна частина кодується окремо та займає один байт у результаті.

Позиції всередині кодового блока нумеруються зліва направо, від старшого біта байта до молодшого:

| Позиція | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Вміст | p1 | p2 | d1 | p4 | d2 | d3 | d4 | p8 |

`d1, d2, d3, d4` — початкові чотири біти, від старшого до молодшого. `p1, p2, p4` — перевірочні біти звичайного коду Геммінга `(7,4)`. `p8` — додатковий біт парності для всього блока.

Використовується парна кількість одиниць у кожній перевірці. Операція XOR, позначена в C# як `^`, дає `1`, якщо кількість одиниць у її аргументах непарна:

```text
p1 = d1 XOR d2 XOR d4
p2 = d1 XOR d3 XOR d4
p4 = d2 XOR d3 XOR d4
p8 = p1 XOR p2 XOR d1 XOR p4 XOR d2 XOR d3 XOR d4
```

Наприклад, ASCII-символ `A` — байт `01000001`. Його частини `0100` і `0001` перетворюються на `10011001` і `11010010`. Отже, закодований результат містить два байти: `10011001 11010010`.

## Як працює виправлення

Декодер повторно перевіряє групи позицій:

```text
s1 = bit1 XOR bit3 XOR bit5 XOR bit7
s2 = bit2 XOR bit3 XOR bit6 XOR bit7
s4 = bit4 XOR bit5 XOR bit6 XOR bit7
syndrome = s1 + 2 * s2 + 4 * s4
parity = XOR усіх восьми бітів
```

`syndrome` називається синдромом. За умови однієї помилки його значення вказує на її позицію серед перших семи бітів. У коді цей самий результат отримано через XOR номерів позицій, у яких стоїть `1`.

| Синдром | Загальна парність | Дія |
| --- | --- | --- |
| 0 | 0 | Помилок немає; читаємо інформаційні біти. |
| 1–7 | 1 | Змінюємо біт у позиції, на яку вказує синдром. |
| 0 | 1 | Змінюємо восьмий біт, тобто додаткову парність. |
| 1–7 | 0 | Виявлено невиправну помилку; за умови не більше двох помилок це дві помилки в блоці. |

Після виправлення декодер бере біти з позицій `3, 5, 6, 7`. Дві відновлені чотирибітні частини з'єднуються в початковий байт.

## Що роблять методи

| Метод | Призначення |
| --- | --- |
| `Main` | Обирає режим файла або рядка, читає вхід і виводить результат. |
| `Encode` | Ділить кожен байт на дві частини та кодує їх. |
| `EncodeNibble` | Обчислює чотири перевірочні біти й утворює восьмибітний блок. |
| `Decode` | Перевіряє довжину входу та відновлює байти з пар кодових блоків. |
| `DecodeNibble` | Обчислює синдром і парність, виправляє помилку та повертає чотири інформаційні біти. |
| `GetBit` | Читає біт у заданій позиції кодового блока. |
| `PrintUsage` | Виводить коротку інструкцію англійською. |

## Формат і межі виправлення

- Файл `.ham` містить лише кодові блоки. Заголовка та таблиць немає.
- На кожен початковий байт припадають два закодовані байти. Тому довжина закодованого файла завжди парна, а порожній вхід дає порожній результат.
- Можна виправити багато помилок у файлі, якщо в кожному восьмибітному блоці змінено не більше одного біта. Це стосується також перевірочних бітів.
- Дві помилки в одному блоці виявляються, але не виправляються. Декодер завершується з `Error: uncorrectable block.` і не створює вихідного файла.
- Для трьох і більше помилок у блоці правильне відновлення або виявлення пошкодження не гарантується.
- Код розрахований на зміну значень бітів. Видалення, додавання або перестановку блоків він не виправляє. Без заголовка довільний файл парної довжини не завжди можна відрізнити від закодованих даних.
- Увесь вхід і результат зберігаються в пам'яті.
- Код завершення `0` означає успіх, `1` — помилку.

Властивості розширеного коду пояснено також у [навчальному матеріалі University of New Brunswick](https://www.ece.unb.ca/tervo/ece4253/hamming.shtml).

## Перевірка

```powershell
./HammingCoding/tests/verify.ps1
```

Скрипт збирає обидві програми й перевіряє всі 16 чотирибітних значень, кожну позицію одиничної помилки та кожну пару позицій подвійної помилки. Також перевіряються файли з усіма 256 значеннями байта, випадкові дані, порожній вхід, UTF-8, рядки, виправлення багатьох помилок у різних блоках та захист наявних вихідних файлів від перезапису. Тимчасові файли видаляються після перевірки.
