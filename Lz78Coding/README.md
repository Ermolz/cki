# Стиснення LZ-78 на C#

Проєкт містить дві окремі консольні програми для стиснення без втрат:

- `Compress/Lz78Compress.cs` читає файл або рядок і створює архів LZ-78.
- `Decompress/Lz78Decompress.cs` читає архів і відновлює початкові дані.

Обидві програми написані на C# для .NET 8, без сторонніх бібліотек. Повідомлення короткі й англомовні. Файли обробляються як послідовності байтів, тому підтримуються текст, зображення та інші двійкові дані. Початкове кодування файла й переведення рядків зберігаються.

## Збирання й запуск

Команди нижче виконуються з кореня репозиторію:

```powershell
dotnet build Lz78Coding/Compress/Lz78Compress.csproj -c Release
dotnet build Lz78Coding/Decompress/Lz78Decompress.csproj -c Release
```

Стиснення та відновлення файла:

```powershell
dotnet run --project Lz78Coding/Compress/Lz78Compress.csproj -c Release --no-build -- input.txt compressed.lz78
dotnet run --project Lz78Coding/Decompress/Lz78Decompress.csproj -c Release --no-build -- compressed.lz78 restored.txt
```

Ім'я вихідного файла для відновлення можна не вказувати. Тоді декодер створить `compressed.lz78.restored`:

```powershell
dotnet run --project Lz78Coding/Decompress/Lz78Decompress.csproj -c Release --no-build -- compressed.lz78
```

Якщо вихідний файл уже існує, програма повідомить про помилку й не перезапише його. Вихідна папка має існувати. Для шляхів із пробілами використовуйте лапки. Параметр `--no-build` застосовується після збирання проєктів.

Для рядків перша програма переводить текст у UTF-8 і виводить архів як Base64. Друга приймає цей Base64 та виводить відновлений текст без додаткового переведення рядка:

```powershell
$archive = dotnet run --project Lz78Coding/Compress/Lz78Compress.csproj -c Release --no-build -- --text "Привіт, світе!"
dotnet run --project Lz78Coding/Decompress/Lz78Decompress.csproj -c Release --no-build -- --text $archive
```

Base64 лише представляє двійковий архів у текстовому вигляді. Для довільних байтів використовуйте файловий режим. `--help` або `-h` показує підказку. Код завершення `0` означає успіх, `1` — помилку.

## Як працює LZ-78

LZ-78 будує словник фраз під час читання вхідних даних. На початку існує лише запис 0 — порожня фраза. Програма шукає найдовший уже відомий префікс і додає наступний байт. Нова фраза передається як пара «індекс префікса, наступний байт» та отримує новий індекс у словнику.

Наприклад, рядок `ABABABA` розбивається на `A | B | AB | ABA`:

| Новий індекс | Фраза | Передана пара |
| ---: | --- | --- |
| 1 | `A` | `(0, A)` |
| 2 | `B` | `(0, B)` |
| 3 | `AB` | `(1, B)` |
| 4 | `ABA` | `(3, A)` |

Декодер починає з такого самого порожнього словника. Для кожної пари він бере фразу за індексом, додає наступний байт, записує результат і додає нову фразу до словника. Тому словник не потрібно зберігати в архіві: обидві програми відтворюють його однаково. Таблиця ймовірностей також не потрібна.

Ширина індексу дорівнює `ceil(log2(k))`, де `k` — кількість записів перед поточною парою, включно з порожньою фразою. Для одного запису індекс займає 0 бітів, для двох — 1 біт, для трьох або чотирьох — 2 біти. Наступний байт завжди займає 8 бітів. Програми стискають значення байтів 0–255, а не окремі біти алфавіту `{0,1}`.

Якщо в кінці входу залишається вже відома фраза, кодер записує лише її індекс. Наприклад, для `AA` спочатку передається `(0, A)`, а потім кінцеве посилання на запис 1. Декодер розпізнає кінцеве посилання за кількістю бітів, що залишилися в потоці; новий запис при цьому не додається.

## Формат архіву

Власний формат має сигнатуру `LZ78`; звичайне розширення файла — `.lz78`. Числові поля записуються у порядку little-endian.

| Поле | Розмір | Призначення |
| --- | ---: | --- |
| Сигнатура `LZ78` | 4 байти | Позначення формату |
| Початкова довжина | 8 байтів | Кількість байтів до стиснення |
| Кількість значущих бітів | 8 байтів | Довжина потоку пар і кінцевого посилання |
| Код LZ-78 | `ceil(бітів / 8)` байтів | Упаковані індекси та наступні байти |

Біти записуються від старшого розряду до молодшого. Невикористані біти останнього байта заповнюються нулями; вони не входять до кількості значущих бітів. Порожній вхід утворює архів із заголовка довжиною 20 байтів.

## Що робить код

У програмі стиснення `Main` обробляє аргументи й введення/виведення, `Compress` будує словник переходів «індекс префікса, байт → індекс нової фрази», `IndexWidth` визначає ширину індексу, а `BitWriter` пакує біти у байти. Перехід у словнику дозволяє шукати відомі фрази без створення довгих рядків.

У програмі відновлення `Decompress` перевіряє архів і послідовно читає пари через `BitReader`. Кожна словникова `Entry` містить індекс префікса, останній байт і довжину фрази. `WritePhrase` проходить цими посиланнями та відновлює байти фрази у вихідному масиві. Повні копії всіх фраз у словнику не зберігаються.

Короткий або майже випадковий файл може збільшитися через заголовок і словникові індекси. Обидві програми завантажують файл та результат у пам'ять; словник не скидається. Декодер перевіряє сигнатуру, довжини, індекси й доповнювальні біти. Контрольної суми немає, тому не кожне пошкодження можна виявити.

## Перевірка

```powershell
./Lz78Coding/tests/verify.ps1
```

Скрипт збирає обидві програми й перевіряє побайтне відновлення файлів, рядки UTF-8, порожній вхід, усі значення байта, повторення, випадкові дані, кінцеві посилання та помилкові архіви. Тимчасові файли видаляються після завершення.
