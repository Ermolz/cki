# Арифметичне кодування

Це дві окремі консольні програми C# (.NET 8): `ArithmeticCompress` стискає файл або рядок, а `ArithmeticDecompress` відновлює його. Програми працюють з байтами, тому файл може містити текст, зображення чи будь-які інші дані. Стискання є безвтратним: відновлені байти збігаються з початковими.

## Як запустити

Команди виконуються з кореня репозиторію:

```powershell
dotnet build ArithmeticCoding/Compress/ArithmeticCompress.csproj -c Release
dotnet build ArithmeticCoding/Decompress/ArithmeticDecompress.csproj -c Release

dotnet run --project ArithmeticCoding/Compress/ArithmeticCompress.csproj -c Release --no-build -- input.txt compressed.arc
dotnet run --project ArithmeticCoding/Decompress/ArithmeticDecompress.csproj -c Release --no-build -- compressed.arc restored.txt
```

Для рядка перша програма виводить архів як Base64, щоб двійкові дані можна було передати через консоль. Отриманий рядок Base64 треба підставити до другої команди:

```powershell
dotnet run --project ArithmeticCoding/Compress/ArithmeticCompress.csproj -c Release --no-build -- --text "Привіт!"
dotnet run --project ArithmeticCoding/Decompress/ArithmeticDecompress.csproj -c Release --no-build -- --text "Base64_з_попередньої_команди"
```

Вихідний файл не перезаписується, якщо вже існує. Для перевірки виконайте `./ArithmeticCoding/tests/verify.ps1`.

## Ідея алгоритму

Програма підраховує, скільки разів кожен із 256 можливих байтів зустрічається у вхідних даних. Це модель частот саме для поточного файла або рядка. До моделі додається спеціальний символ кінця даних із частотою 1. Відносні частоти визначають частки інтервалу, які отримують символи.

На початку арифметичний код має повний числовий інтервал. Для кожного вхідного байта `ArithmeticCompress` залишає в ньому тільки підінтервал цього символу. Наступний байт звужує вже отриманий інтервал. Часті символи отримують ширші підінтервали, тому довгі послідовності з ними зазвичай потребують менше бітів. Наприкінці кодується символ кінця даних. На відміну від Гаффмана, програма не призначає окремий двійковий код кожному символу: один потік бітів описує послідовне звуження інтервалу для всього повідомлення.

Для точності використовуються 64-бітні цілі межі `low` і `high`; проміжне множення та ділення виконується через `UInt128`. Коли старший біт меж стає визначеним, кодер записує його та зсуває інтервал. Якщо межі опиняються навколо середини, кодер відкладає відповідні біти до наступного визначеного біта. Так інтервал не стає надто вузьким.

`ArithmeticDecompress` читає частоти з архіву та будує такі самі накопичені межі для всіх символів. За черговими бітами архіву він визначає, у який підінтервал потрапляє кодове число, відновлює байт і повторює звуження та зсув. Декодування завершується на спеціальному символі кінця. Програма також перевіряє заголовок, таблицю частот і довжину відновлених даних.

## Що зберігається в `.arc`

Архів містить сигнатуру `ARC1`, довжину початкових даних, кількість бітів кодового потоку, кількість різних байтів, таблицю пар «байт — його частота» та упаковані біти. Таблиця потрібна декодеру: без неї він не зможе повторити той самий поділ інтервалу. Службовий символ кінця має наперед визначену частоту 1 і в таблиці не записується.

Порожній файл, файл з одним повторюваним байтом і всі 256 значень байта підтримуються. Для короткого або майже випадкового файла архів може бути більшим за вхідний файл через заголовок і таблицю частот.
