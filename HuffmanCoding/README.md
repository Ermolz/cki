# Кодування Гаффмана на C#: стиснення та відновлення

У папці містяться **дві окремі консольні програми**. `HuffmanCompress` стискає файл або рядок кодом Гаффмана, а `HuffmanDecompress` відновлює початкові дані. Стиснення відбувається без втрат: після відновлення кожен байт має те саме значення, що й до стиснення.

Частоти символів обчислюються **для кожного входу окремо**. Таблиця частот записується до архіву, тому для декодування достатньо самого архіву. У файловому режимі «символ» означає одне зі 256 можливих значень **байта**, а не літеру Unicode.

## Склад проєкту

```text
HuffmanCoding/
├── Compress/
│   ├── HuffmanCompress.cs         код програми стиснення
│   └── HuffmanCompress.csproj     окремий проєкт .NET
├── Decompress/
│   ├── HuffmanDecompress.cs       код програми відновлення
│   └── HuffmanDecompress.csproj   окремий проєкт .NET
├── global.json                  вибір стабільного .NET SDK 8
└── README.md
```

Увесь вихідний код C# розміщений у двох файлах `.cs`. Кожен проєкт можна зібрати незалежно. Правило побудови дерева реалізовано в обох програмах, бо декодер відтворює те саме дерево за таблицею частот.

## Вимоги та збирання

Потрібен **.NET SDK 8.0**. Сторонніх пакетів немає. Команди нижче виконуйте з папки `HuffmanCoding`:

```powershell
cd HuffmanCoding
dotnet build Compress/HuffmanCompress.csproj -c Release
dotnet build Decompress/HuffmanDecompress.csproj -c Release
```

Параметр `--no-build` у наступних прикладах означає, що програми вже зібрано. Якщо збірки ще немає, приберіть його або спочатку виконайте дві команди `dotnet build`.

## Робота з файлами

Стиснення файлу:

```powershell
dotnet run --project Compress/HuffmanCompress.csproj -c Release --no-build -- input.txt compressed.huf
```

Перший аргумент — наявний вхідний файл, другий — **новий** файл архіву. Суфікс `.huf` зручний, але програма не вимагає саме його.

Відновлення з явним іменем вихідного файлу:

```powershell
dotnet run --project Decompress/HuffmanDecompress.csproj -c Release --no-build -- compressed.huf restored.txt
```

Ім’я вихідного файлу можна не вказувати:

```powershell
dotnet run --project Decompress/HuffmanDecompress.csproj -c Release --no-build -- compressed.huf
```

Тоді буде створено `compressed.huf.restored`: декодер додає `.restored` до шляху архіву. Початкове ім’я `input.txt` в архіві не зберігається, отже визначити його автоматично неможливо. Якщо результат уже існує, програма повідомить про помилку і **не перезапише** його. Вихідна папка має існувати заздалегідь. Для шляхів із пробілами використовуйте лапки.

Обидві програми читають файл як послідовність байтів. Працюють текстові файли, зображення та інші двійкові дані. Зберігаються початкове кодування тексту, BOM і символи переведення рядка. Успішна файлова операція друкує лише `Saved: <шлях>`; повідомлення програми короткі й англомовні.

Перевірка результату в PowerShell:

```powershell
(Get-FileHash input.txt).Hash -eq (Get-FileHash restored.txt).Hash
```

Значення `True` означає, що хеші SHA-256 збігаються. Для автоматично названого результату замініть `restored.txt` на `compressed.huf.restored`.

## Робота з рядками

Стиснення рядка:

```powershell
dotnet run --project Compress/HuffmanCompress.csproj -c Release --no-build -- --text "Привіт, світе!"
```

Результат — **один рядок Base64**, що містить той самий двійковий архів `HUF1`, який створюється для файлів. Щоб відновити текст, передайте отриманий Base64 другій програмі:

```powershell
dotnet run --project Decompress/HuffmanDecompress.csproj -c Release --no-build -- --text "ОТРИМАНИЙ_BASE64"
```

У PowerShell ці два кроки можна поєднати:

```powershell
$compressed = dotnet run --project Compress/HuffmanCompress.csproj -c Release --no-build -- --text "Привіт, світе!"
dotnet run --project Decompress/HuffmanDecompress.csproj -c Release --no-build -- --text $compressed
```

Перед стисненням рядок перетворюється на UTF-8, тому працюють українські літери, розділові знаки та емодзі. Декодер у режимі `--text` вимагає коректний UTF-8 і виводить текст **без додаткового переведення рядка**. Для довільних двійкових даних використовуйте файловий режим. Base64 лише робить архів придатним для виведення в термінал; сам по собі він не стискає дані й збільшує їхній запис приблизно на третину.

Довідка: `--help` або `-h`. Код завершення `0` означає успіх, `1` — помилку.

## Як працює алгоритм Гаффмана

Звичайний байт займає вісім бітів. Код Гаффмана замінює кожне значення байта послідовністю бітів змінної довжини: часті значення зазвичай отримують короткі коди, рідкісні — довші. Імовірність можна обчислити як `частота / загальна кількість байтів`, але ділити всі частоти на ту саму кількість для роботи алгоритму не потрібно.

Для ASCII-послідовності `AAAAABBC` маємо:

| Символ | Частота | Імовірність |
| --- | ---: | ---: |
| `A` | 5 | 5/8 |
| `B` | 2 | 2/8 |
| `C` | 1 | 1/8 |

Побудова дерева:

1. Для кожного значення байта з ненульовою частотою створюється лист із відповідною вагою.
2. Два вузли з найменшими вагами вилучаються з черги з пріоритетами.
3. Вони стають лівою та правою дитиною нового вузла, вага якого дорівнює сумі їхніх ваг.
4. Новий вузол повертається в чергу. Кроки повторюються до появи одного кореня.
5. Перехід ліворуч позначається `0`, праворуч — `1`. Шлях від кореня до листа утворює код байта.

У прикладі спочатку об’єднуються `C:1` та `B:2`, потім утворений вузол ваги `3` і `A:5`. Отримуємо `A = 1`, `B = 01`, `C = 00`:

```text
AAAAABBC → 1 1 1 1 1 01 01 00 → 11111010100
```

Це 11 значущих бітів замість 64 бітів восьми ASCII-байтів. Наведене порівняння **не враховує** заголовок і таблицю частот архіву.

Код є **префіксним**: жоден код не є початком іншого. Під час декодування програма читає біти, рухається деревом до листа, записує відповідний байт і повертається до кореня. Роздільники між кодами не потрібні.

Якщо кілька вузлів мають однакову вагу, першим обирається вузол із меншим найменшим значенням байта серед його листків. Перший вилучений вузол стає лівою дитиною. Це правило робить побудову дерева однозначною для обох програм. Якщо у вхідних даних є лише один різновид байта, йому надається код `0`.

## Формат архіву `HUF1`

Числові поля записано у порядку **little-endian** — від молодшого байта до старшого.

| Поле | Розмір | Призначення |
| --- | ---: | --- |
| Сигнатура `HUF1` | 4 байти | Ідентифікатор формату та версії |
| Довжина початкових даних | 8 байтів | Кількість байтів до стиснення |
| Кількість значущих бітів | 8 байтів | Довжина закодованого потоку без доповнення |
| Кількість різних байтів | 2 байти | Число записів таблиці, від 0 до 256 |
| Таблиця частот | 9 байтів на запис | Значення байта: 1 байт; частота: 8 байтів |
| Закодований потік | `ceil(бітів / 8)` байтів | Коди, упаковані у байти |

Записи таблиці відсортовано за зростанням значення байта. У кожному вихідному байті перший біт коду займає старший розряд. Невикористані молодші біти останнього байта заповнюються нулями. Декодер читає тільки вказану кількість **значущих** бітів. Загальний розмір архіву:

```text
22 + 9 × кількість різних байтів + ceil(кількість значущих бітів / 8)
```

Для `AAAAABBC`: `22 + 9 × 3 + 2 = 51` байт. Архів більший за короткий вхід через накладні витрати на таблицю. Фактичний розмір завжди залежить від кількості різних байтів та довжин їхніх кодів.

## Пояснення вихідного коду

### `Compress/HuffmanCompress.cs`

| Елемент | Призначення |
| --- | --- |
| `Main` | Розбирає аргументи, читає файл або рядок, викликає стиснення та записує результат у новий файл чи виводить Base64. |
| `Compress` | Рахує частоти у масиві з 256 елементів, записує заголовок і таблицю, перетворює байти на коди й пакує біти. |
| `BuildTree` | Створює дерево через `PriorityQueue`, що видає вузли з найменшою вагою. |
| `BuildCodes` | Обходить дерево, додаючи `0` для лівої та `1` для правої гілки. |
| `Node` | Зберігає вагу, значення байта листа й дочірні вузли; у внутрішнього вузла `Symbol` порожній. |

### `Decompress/HuffmanDecompress.cs`

| Елемент | Призначення |
| --- | --- |
| `Main` | Розбирає аргументи, читає файл або Base64, створює новий вихідний файл чи виводить рядок UTF-8. |
| `Decompress` | Перевіряє заголовок і таблицю, відтворює дерево, читає біти та перевіряє кількість отриманих байтів. |
| `BuildTree` | Повторює те саме правило об’єднання вузлів, що й програма стиснення. |
| `CountBits` | Обчислює очікувану кількість бітів із частот і глибин листків для перевірки архіву. |
| `Node` | Представляє той самий тип вузла дерева. |

## Особливі випадки й обмеження

- Порожній вхід дає архів із 22 байтів, порожньою таблицею та без закодованого потоку; відновлюється порожній файл або рядок.
- Один унікальний байт має код `0`; кількість повторень міститься в заголовку. Підтримуються також усі 256 значень байта.
- Короткий або майже рівномірний вхід може збільшитися після стиснення: заголовок і таблиця також займають місце. На повторюваних даних результат часто менший.
- Обидві програми завантажують вхід і результат до оперативної пам’яті повністю. Для дуже великих файлів потокову обробку не реалізовано.
- Декодер відхиляє помітно пошкоджені архіви: неправильну сигнатуру, частоти, довжину потоку та доповнювальні біти. Контрольної суми немає, тому виявити **будь-яке** пошкодження неможливо.
- Підтримується лише власний формат `HUF1`, а не ZIP, GZIP чи формат `SFC1` із сусіднього проєкту.

Підрахунок частот потребує одного проходу по входу. Для `k ≤ 256` різних байтів побудова дерева потребує приблизно `O(k log k)` операцій; кодування й декодування залежать від кількості оброблених бітів.

## Перевірка

Програми зібрано з .NET SDK 8 без помилок і попереджень. Перевірено роботу з файлами та рядками, порожній вхід, один символ, усі 256 значень байта, випадкові двійкові дані, UTF-8, відмову від перезапису й обробку помилкового архіву. Для кожного коректного входу відновлений результат збігся з початковим побайтно.
