# Кодування Шеннона–Фано на C#: стиснення та відновлення

Проєкт складається з **двох окремих консольних програм**. `ShannonFanoCompress` стискає файл або рядок кодом Шеннона–Фано, а `ShannonFanoDecompress` відновлює початкові дані. Після відновлення файл збігається з початковим побайтно.

Частоти появи символів програма обчислює **для кожного входу окремо** й записує в архів. Зовнішня таблиця ймовірностей не потрібна. У файловому режимі символом вважається **байт** із можливими значеннями від 0 до 255. Наприклад, одна літера UTF-8 може складатися з кількох байтів; програма стискає ці байти, а після відновлення отримує ту саму літеру.

## Склад проєкту

```text
ShannonFanoCoding/
├── Compress/
│   ├── ShannonFanoCompress.cs         код програми стиснення
│   └── ShannonFanoCompress.csproj     окремий проєкт .NET
├── Decompress/
│   ├── ShannonFanoDecompress.cs       код програми відновлення
│   └── ShannonFanoDecompress.csproj   окремий проєкт .NET
├── global.json                      вибір стабільного .NET SDK 8
└── README.md
```

Увесь вихідний код C# розміщений у двох файлах `.cs`. Програми збираються незалежно. Алгоритм побудови дерева є в обох файлах, бо декодер повинен відтворити коди лише за таблицею частот із архіву.

## Вимоги та збирання

Потрібен **.NET SDK 8.0**. Сторонніх пакетів немає. Перейдіть до папки проєкту й зберіть обидві програми:

```powershell
cd ShannonFanoCoding
dotnet build Compress/ShannonFanoCompress.csproj -c Release
dotnet build Decompress/ShannonFanoDecompress.csproj -c Release
```

Наступні приклади використовують `--no-build`, тобто спочатку потрібно виконати збирання. За потреби цей параметр можна прибрати.

## Робота з файлами

Стиснення:

```powershell
dotnet run --project Compress/ShannonFanoCompress.csproj -c Release --no-build -- input.txt compressed.sfc
```

Перший аргумент — наявний вхідний файл, другий — **новий** файл архіву. Розширення `.sfc` зручне для розпізнавання формату, але не є обов’язковим.

Відновлення:

```powershell
dotnet run --project Decompress/ShannonFanoDecompress.csproj -c Release --no-build -- compressed.sfc restored.txt
```

На відміну від сусіднього проєкту Гаффмана, тут **потрібно вказати обидва шляхи**: шлях архіву та шлях нового вихідного файлу. Для шляхів із пробілами використовуйте лапки. Вихідна папка повинна існувати. Наявні вихідні файли не перезаписуються.

Програми працюють із байтами, тому підтримують текстові й двійкові файли. Зберігаються кодова сторінка тексту, BOM, переведення рядків і всі інші байти. Перевірити результат у PowerShell можна за SHA-256:

```powershell
(Get-FileHash input.txt).Hash -eq (Get-FileHash restored.txt).Hash
```

Значення `True` означає, що вміст файлів збігається за хешем.

## Робота з рядками

Для рядка замість імені файлу передайте `--text`:

```powershell
dotnet run --project Compress/ShannonFanoCompress.csproj -c Release --no-build -- --text "Привіт, світе!"
```

Результат — **один рядок Base64**, що представляє двійковий архів з таблицею частот і закодованими бітами. Щоб відновити текст:

```powershell
dotnet run --project Decompress/ShannonFanoDecompress.csproj -c Release --no-build -- --text "ОТРИМАНИЙ_BASE64"
```

Можна передати результат однієї програми іншій без ручного копіювання:

```powershell
$compressed = dotnet run --project Compress/ShannonFanoCompress.csproj -c Release --no-build -- --text "Привіт, світе!"
dotnet run --project Decompress/ShannonFanoDecompress.csproj -c Release --no-build -- --text $compressed
```

У режимі рядка текст спочатку перетворюється на UTF-8; декодер вимагає коректний UTF-8 і виводить початковий текст без додаткового переведення рядка. Для довільних двійкових даних використовуйте файловий режим. Base64 потрібен лише для передавання архіву як друкованого рядка; він не стискає дані та збільшує їхній текстовий запис приблизно на третину.

`--help` або `-h` виводить підказку. Код завершення `0` означає успіх, `1` — помилку.

## Як працює алгоритм Шеннона–Фано

Ідея алгоритму — надати коротші бітові коди частим символам і довші коди рідкісним. Імовірність символу дорівнює його частоті, поділеній на загальну кількість символів. Програма використовує самі частоти: спільний знаменник не впливає ні на порядок символів, ні на вибір межі груп.

Для ASCII-послідовності `AAAAABBC` частоти такі:

| Символ | Частота | Імовірність |
| --- | ---: | ---: |
| `A` | 5 | 5/8 |
| `B` | 2 | 2/8 |
| `C` | 1 | 1/8 |

Алгоритм будує дерево **згори донизу**:

1. Символи сортуються за спаданням частоти. За однакової частоти першим іде байт із меншим числовим значенням.
2. У впорядкованому списку розглядаються межі між сусідніми символами. Обирається межа, за якої суми частот лівої та правої груп найближчі. Обидві групи мають бути непорожніми.
3. Символам лівої групи до коду додається `0`, правої — `1`.
4. Кожна група з кількох символів ділиться знову. Процес завершується, коли в кожній групі залишився один символ.

Для `A:5, B:2, C:1` можливі розбиття `A | B,C` із сумами `5` та `3` і `A,B | C` із сумами `7` та `1`. Перше розбиття має меншу різницю, тому обирається воно. Далі `B,C` ділиться на окремі символи. Отримуємо `A = 0`, `B = 10`, `C = 11`:

```text
AAAAABBC → 0 0 0 0 0 10 10 11 → 00000101011
```

Це 11 значущих бітів замість 64 бітів восьми початкових ASCII-байтів. Порівняння **не враховує** заголовок і таблицю частот. Якщо кілька меж дають однакову найменшу різницю, обирається **перша межа зліва**. Декодер застосовує ті самі правила, тому відновлює те саме дерево.

Коди є **префіксними**: жоден код не є початком іншого. Декодер читає біти послідовно: `0` означає перехід ліворуч у дереві, `1` — праворуч. Досягнувши листа, він записує байт і повертається до кореня. Роздільники між кодами не потрібні. Якщо вхід містить лише один різновид байта, йому надається код `0`.

### Відмінність від коду Гаффмана

| Ознака | Шеннон–Фано | Гаффман |
| --- | --- | --- |
| Побудова дерева | Згори донизу: поділ впорядкованого списку | Знизу вгору: об’єднання двох найлегших вузлів |
| Правило кроку | Мінімізація різниці сум двох груп | Вибір двох вузлів із найменшими вагами |
| Довжина коду | Не завжди мінімальна серед префіксних кодів | Мінімальна серед двійкових префіксних кодів для заданих частот |
| Відновлення | Прохід деревом за бітами | Прохід деревом за бітами |

Обидва алгоритми працюють без втрат, але їхні архіви мають різні формати й не декодуються навхрест.

## Формат архіву `SFC1`

Числові поля записано у порядку **little-endian** — від молодшого байта до старшого.

| Поле | Розмір | Призначення |
| --- | ---: | --- |
| Сигнатура `SFC1` | 4 байти | Ідентифікатор формату та версії |
| Довжина початкових даних | 8 байтів | Кількість байтів до стиснення |
| Кількість значущих бітів | 8 байтів | Довжина закодованого потоку без доповнення |
| Кількість різних байтів | 2 байти | Число записів таблиці, від 0 до 256 |
| Таблиця частот | 9 байтів на запис | Значення байта: 1 байт; частота: 8 байтів |
| Закодований потік | `ceil(бітів / 8)` байтів | Коди, упаковані у байти |

Записи таблиці впорядковано **за значенням байта**, а не за частотою; після читання декодер сортує їх за правилами алгоритму. Перший біт коду записується в старший розряд вихідного байта. Невикористані молодші біти останнього байта заповнюються нулями. Декодер читає лише вказану кількість значущих бітів.

Повний розмір архіву:

```text
22 + 9 × кількість різних байтів + ceil(кількість значущих бітів / 8)
```

Для `AAAAABBC` архів займає `22 + 9 × 3 + 2 = 51` байт. Накладні витрати перевищують виграш на такому короткому вході. Для великих повторюваних даних стиснення може бути відчутним.

## Пояснення вихідного коду

### `Compress/ShannonFanoCompress.cs`

| Елемент | Призначення |
| --- | --- |
| `Main` | Розбирає аргументи, читає файл або рядок UTF-8, створює новий архів чи виводить Base64. |
| `Compress` | Підраховує частоти в масиві з 256 елементів, записує таблицю та пакує коди в байти. |
| `BuildTree` | Вибирає присутні байти й сортує їх за спаданням частот із визначеним правилом для рівності. |
| `BuildSubtree` | Шукає найкращу межу між двома групами й рекурсивно будує ліве та праве піддерева. |
| `BuildCodes` | Обходить дерево, додаючи `0` зліва та `1` справа. |
| `Node` | Зберігає вагу вузла, значення байта в листі та посилання на дочірні вузли. |

### `Decompress/ShannonFanoDecompress.cs`

| Елемент | Призначення |
| --- | --- |
| `Main` | Розбирає аргументи, читає архів або Base64, записує новий файл чи виводить рядок UTF-8. |
| `Decompress` | Перевіряє заголовок, частоти й довжину потоку, читає біти та відновлює байти. |
| `BuildTree` і `BuildSubtree` | Відтворюють дерево за тим самим правилом сортування й поділу. |
| `CountBits` | Обчислює очікувану кількість бітів для перевірки архіву. |
| `Node` | Представляє лист або внутрішній вузол відновленого дерева. |

## Особливі випадки й обмеження

- Порожній вхід дає 22-байтовий архів із порожньою таблицею; відновлюється порожній файл або рядок.
- Один унікальний байт отримує код `0`. Підтримуються також усі 256 значень байта.
- Архів може бути більшим за початковий файл через заголовок і таблицю, особливо для короткого або майже рівномірного входу.
- Вхід і результат обробляються цілком в оперативній пам’яті; потокову обробку дуже великих файлів не реалізовано.
- Декодер перевіряє структуру архіву, частоти, кількість бітів і доповнення, але контрольної суми немає: не кожне пошкодження можна виявити.
- Підтримується тільки власний формат `SFC1`, а не ZIP, GZIP чи `HUF1` із проєкту Гаффмана.

Якщо `k ≤ 256` — кількість різних значень байта, сортування потребує приблизно `O(k log k)` операцій. Послідовний перегляд меж на кожному рівні може дати до `O(k²)` операцій для побудови дерева. Підрахунок частот робить один прохід по входу.

## Перевірка

Обидві програми зібрано з .NET SDK 8 без помилок і попереджень. Перевірено побайтне відновлення порожніх, текстових і двійкових файлів; рядки UTF-8; один символ; усі 256 значень байта; випадкові дані; відмову від перезапису й помилкові архіви. Для `AAAAABBC` перевірено саме коди Шеннона–Фано `A=0`, `B=10`, `C=11`.
